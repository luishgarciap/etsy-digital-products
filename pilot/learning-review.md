## Learning questions

For each pilot, determine:

- which hypothesis was supported;
- which hypothesis was contradicted;
- what remains unresolved;
- whether the result is a product problem, listing/search problem, price/economics problem or insufficient-evidence problem;
- what evidence would materially change the next decision.

## Diagnostic guide

| Observed pattern | Interpretation to test |
|---|---|
| Views/search traffic but no sales | Product fit, presentation, price or buyer intent |
| Sales but weak contribution | Price, bundle design, fees or production/support effort |
| Strong conversion but little traffic | Search term, listing relevance or catalogue breadth |
| One product family repeatedly stronger | Evidence for expansion into adjacent products/bundles |
| Repeated buyer request | Candidate input for next FRAME |
| Little traffic + weak demand evidence | Candidate for rejection/deprioritisation |

## Exit decision

At the end of the learning review, recommend one of the following:

1. **ITERATE** — return to [Opportunity frame](../discovery/opportunity-frame.md) with a narrower/new question;
2. **EXIT TO OPERATE / EXPAND** — the key hypotheses are sufficiently validated;
3. **PIVOT** — a different product family should become the new frame;
4. **PAUSE / STOP** — evidence does not justify further investment now.

Returning to FRAME does not erase prior evidence. The next frame starts from this learning and Git preserves the full history.
